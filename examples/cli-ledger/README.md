# 一次完整运行的产物（可复现）

**任务原文**：「做一个命令行记账工具，能记一笔、查余额、看记录。做得实用点。」

**跑法**：deepseek-v4.1-flash，单进程 opencode，13 分钟，749 行 Python。

这个目录不是"示意"，是**当时真实产出的快照**——代码能跑，验证能复现。

---

## 怎么复现

```bash
cd examples/cli-ledger

python verify.py           # 期望 20/20 PASS，exit 0
python mutation_test.py    # 期望 19/20 FAIL（这是对的，见下）
```

**注意 `mutation_test.py` 的 `FAIL` 是成功**：

它把 `balance()` 改成永远返回 0，然后跑同一份 `verify.py`。
如果 verify 仍然全绿，说明那条断言是假的；现在它变成 19/20，**说明断言真的能被打败**。

跑完会在 `evidence/` 下生成带时间戳的新文件（已 gitignore，不会污染仓库）。

## 这份示例证明了什么

| 证明了 | 证据 |
|---|---|
| **A4 回查能抓出无主需求** | `SWARM-PLAN.md` 里挑出 4 条不属于任何技术模块的需求（默认路径、根入口、README、验证脚本），单独成块 C |
| **断言可以被打败** | `verify.py` 20/20 → 变异后 19/20，精确抓到那一条 |
| **逐条打勾能逼出"没验的"** | `FINAL.md` 结尾列了「界面顺眼 / 提示语习惯 / 长期手感」三项明确未验 |
| **skill 本身有 15 处说不清** | `PROBLEMS.md` |

## 这份示例**没有**证明什么

**它只跑了 13 分钟、749 行。** 而 skill 想防的失败（把范围悄悄做小）需要"任务大到必须取舍"才会发生。

这个任务对模型来说太小了——**它有富余把活全做完，所以"缩小范围"根本没机会出现**。

换句话说：**这次跑通只说明流程能走完，不说明它能防住真正的问题。**

完整的验证边界见仓库根目录 README 的「验证到什么程度」一节。
