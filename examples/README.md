# 一次完整运行的产物示例

任务：「做一个命令行记账工具，能记一笔、查余额、看记录。做得实用点。」
规模：749 行 Python / 13 分钟 / deepseek-v4.1-flash

| 文件 | 是什么 | 对应哪一步 |
|---|---|---|
| `RECIPE.md` | 8 个问题 + 范围决策 + 原话条目 + 复述 | recipe 前两步 |
| `SWARM-PLAN.md` | 切域 / done predicate / 接口契约 / 无主需求回查 | swarm Phase A |
| `FINAL.md` | 按原话逐条打勾，报 5/5 | recipe 第四步 |
| `PROBLEMS.md` | 执行时「skill 说不清、只能猜」的 15 处 | 测试反馈 |

**最值得看的是 `SWARM-PLAN.md` 里「A4 回查：每条需求归谁」那一节。**

它抓出了 4 条不属于任何技术模块的需求（默认数据路径、根入口、README、验证脚本），单独成块 C。
不这么做，这 4 条会在切块时直接掉出去——而按模块统计还会显示「全部完成」。

## 注意：这份示例早于当前版本

- 没有 `DELIVERY.md`（`deliver` 是之后才写的）
- `RECIPE.md` 里没有「追问记录」（追问机制是之后加的）
- 范围决策全是「代答」（agent 自己扮演用户），所以按现在的 G1 会把它标成「AI 假设」

看格式可以，别当成"应该长这样"的唯一标准。
