# PROBLEMS：skill 说不清、执行者不得不猜的地方

> 格式：`第几步 | skill 里怎么写的 | 你实际怎么处理的 | 猜的成分有多大`
> 目的：比产出本身更重要——暴露 skill 的真实断点。

| # | 第几步 | skill 里怎么写的 | 实际怎么处理 | 猜的成分 |
|---|---|---|---|---|
| 1 | recipe 第一步 | 用 8 个开放式问题问真实用户 | 真实用户不在，执行者扮演普通用户自问自答；问题与答案都写进 `RECIPE.md` | **100%**（用户缺席） |
| 2 | recipe 第二步 | 范围决策必须由人拍，**AI 不许填** | 用代答答案填表，标注「人（Qx 代答）」；本质仍是 AI 填的，**不满足硬规则** | **高** |
| 3 | recipe 第三步 | 复述后等用户说「对」再动手 | 无用户，代答「对，按这个做」后继续 | **100%** |
| 4 | recipe 第四步 | 按用户原话逐条统计 N/M | 原话没有标点分条，按分句拆成 5 条；「做得实用点」算 1 条，子项只在菜谱里展开 | **中**（条目粒度没定义） |
| 5 | recipe 附则 | 判据写完后要真的破坏一次 | 写 `mutation_test.py`：把 `balance()` 改成恒 0，要求同一份 verify 失败 | 低（做法自定） |
| 6 | swarm A2/A3 | 每块独立目录、物理上不共享；改同一代码库用 git worktree | A（数据层）与 B（命令层）存在库依赖。先冻结接口契约，B 只按契约编码、不读 A 实现；两目录不共享文件 | **中高**（skill 没讲依赖块怎么切） |
| 7 | swarm A4 | 无主需求单独成块 | 把默认数据路径、根入口、README、验证脚本归入 C「收口块」 | 中（跨切面需求怎么归类没写） |
| 8 | swarm Phase B | 所有 worker 在同一个响应里发出去才是并行 | 单进程无法并行；按测试 prompt 的要求串行 A→B→C，并明确声明**不能验证 35% 收益** | **0**（prompt 已指定） |
| 9 | swarm Phase C/D | 没证据重跑，第二次记 gap；报告 PASS/ISSUES/BLOCKED | 额外把「证据文件存在」作为聚合前置，并在报告表加「证据」列 | 低 |
| 10 | verify-app 第二步 | 生成**项目级 skill**（如 `.claude/skills/verify/`），包含六节 | 生成 `verify.py` + `VERIFY.md`（六节写在文档里），没有建 skill 目录 | **中**（prompt 只要求 verify.py/sh） |
| 11 | verify-app CLI/TUI | 用 tmux 会话 / PTY 驱动，证据是终端转录 | Windows 没有 tmux，改用 `subprocess` 管道；在 `VERIFY.md` 列出替身多做的步骤 | **中** |
| 12 | verify-app Evidence | 证据可以是截图 / 终端输出 / 响应体 | CLI 没有截图，用「命令 + 退出码 + stdout/stderr + 账本字节数」 | 低 |
| 13 | verify-app Isolate | 能不能同时跑两个实例？不能就写「禁止并行驱动」 | 验证脚本每次用独立临时文件，可并行跑 verify；但**同一个账本文件禁止两个写进程**，已写进 README | 低 |
| 14 | 全流程 | 没规定产物放哪、证据怎么命名 | 全部放当前目录；证据统一 `evidence/`，文件名带时间戳 | 低 |
| 15 | 术语 | prompt 只给了 `run/store/` 与 `run/todo/` 两个目录名 | 把 `store` 解释为数据层、`todo` 解释为命令层 | **中**（命名与职责的对应没定义） |

## 最值得补进 skill 的三条

1. **recipe**：补「没有真人时怎么办」——允许代答，但必须把每个答案是"人说的"还是"AI 假设的"标出来，并在交付时降级结论。否则"范围必须人拍"在自动化测试里必然被绕过。
2. **swarm**：补「块之间有依赖」的切法——先冻结接口契约，再让各块独立实现；否则 A3 的"零共享"只能靠运气。再补一句：单进程环境不要假装并行，明确声明未验证并行收益。
3. **verify-app**：把「生成项目级 skill」和「生成一个 verify 脚本」统一成两种交付形态（重/轻），并给 CLI 的跨平台驱动方案（Windows 用 subprocess，不必 tmux）。
